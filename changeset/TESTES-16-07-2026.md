## ✗ Bug encontrado (desktop) — launcher de terceiros clobberado

**Sintoma:** após "Voltar ao modo celular", o launcher padrão virou
`com.sec.android.app.launcher` (One UI Home), mas o launcher original do
aparelho era `com.rama.mako`.

**Causa:** o mapeamento FIXO "modo celular = One UI Home"
(`PHONE_HOME_PKG = 'com.sec.android.app.launcher'` em `runner.js`) assume que
o launcher do celular é sempre o da Samsung. Em aparelhos com launcher de
terceiro (Nova, Niagara, mako…), a volta ao modo celular ROUBA o launcher do
usuário e coloca o One UI Home.

**Correção a aplicar (backlog):** ao capturar o estado antes de trocar o home
para o launcher de TV, guardar o launcher REAL que estava ativo (o `prevHome`
já lido) e restaurar ESSE — não o One UI Home fixo. Manter o One UI Home só
como último fallback quando não há launcher anterior legível. Cuidado para não
reintroduzir o problema que o mapeamento fixo resolvia (uma volta que falhou
deixando o launcher de TV como "anterior") — a solução é preferir o launcher
atual SE ele não for o de TV.

**Mitigação no teste:** launcher mako restaurado manualmente via
`cmd package set-home-activity com.rama.mako/.activities.MainActivity`.

## Fase 2 — ponte desktop → mobile (companion)

Perfil "Sala 4k" exportado do registro do desktop e enviado ao companion.

**✔ Funcionou:**
- **Formato idêntico** — o companion leu o mesmo JSON dos perfis nomeados do
  desktop, sem conversão. A UI mostrou "Sala 4k · 3840x2160 · giro 0° · fonte
  1.15x" e "Perfis enviados pelo computador".
- **6 ajustes aplicados AO VIVO, corretos:** fonte 1.15, tela sempre ligada,
  Não Perturbe, 3 escalas de animação = 0, sons silenciados, rotação travada.
  Batem exatamente com o que o desktop faz.
- **Resolução boot-pending confirmada** — `display_size_forced=3840,2160`
  gravado, sem override ao vivo (achado do M0, reproduzido).

**✗ Lacunas encontradas (para o backlog do companion):**
1. **Densidade pareada não aplicada** — no perfil, o 512 vem embutido na task
   `wmsize` (campo `density`); o `applyResolution` do companion só escreve
   `display_size_forced` e ignora a densidade. Resultado: densidade ficou 560.
   Corrigir: o handler de `wmsize` deve escrever também
   `secure display_density_forced` quando a task traz `density`.
2. **Task `home` enterra o companion** — ao aplicar um perfil com `home`, o
   companion lança outro launcher (Projectivy/One UI Home) e sai de primeiro
   plano; o usuário fica sem o botão "Voltar ao modo celular" na tela. Reforça
   a P1 do backlog (tile/gatilho automático para um "voltar" sempre acessível).
   Opção: o companion NÃO executar `home` (deixar o launcher para o desktop),
   ou executá-lo por último e devolver o foco ao próprio app.

**Nota:** a engine de restaurar em si está provada (teste limpo só-fonte, no
M1); a falha aqui foi o foco ser roubado pela task `home`, não o código de
restauração.
