# Diagnóstico e restauração — 21/07/2026 (Galaxy S21 FE, SM-G990E, Android 16, USB)

Sessão de diagnóstico do relato: **após dias de idas e voltas entre modo TV e
modo celular, a interface do S21 FE "não encaixava mais" no celular, mesmo
voltando ao modo inicial e revertendo tudo**. Registro feito com Claude
coletando o estado real via ADB (serial USB `RXCW201M3HV`, que é também o
serial de fábrica).

## O que o registro de reversão mostrava (ANTES)

Arquivo `~/Library/Application Support/dexarmor/revert/RXCW201M3HV.json`:

- `sessionStartedAt: 2026-07-21T20:55Z` (17:55 local) — uma **Reversão
  completa foi executada hoje** e removeu as entradas de interface
  (resolução/dpi/fonte) do registro.
- Sobraram: Max e Paramount+ (reversão `uninstall` falhou — os apps **já não
  existem** no aparelho, ver abaixo) e `tw-rotate` **dormente** (original:
  `accelerometer_rotation=0`, `user_rotation=0` — rotação travada em pé já era
  o estado da usuária antes do DexArmor).
- Perfil "s21fe celular" (16:39 local) com **duas tasks de dpi ao mesmo tempo**
  (`tw-dpi-default` E `tw-dpi-small` com `dpi: 320`) — retrato de um registro
  já confuso: as duas entradas de dpi estavam ativas simultaneamente
  (exclusiveGroup só age nos checkboxes, não no registro).

## O que o aparelho mostrava (ANTES) — em pleno "modo celular"

| Item | Valor encontrado | Fábrica |
|---|---|---|
| `wm size` | Physical 1080x2340, **Override 3840x2160** | sem override |
| `wm density` | Physical 480, **Override 768** | sem override |
| `global display_size_forced` | 3840,2160 | vazio |
| `secure display_density_forced` | 768 | vazio |
| `font_scale` | 1.15 | 1.0 |
| Rotação | accel 0 / rot 0 (= original registrado) | — |
| Launcher padrão | **nenhum** (resolve vazio; One UI Home na tela) | One UI Home |
| Projectivy | **desinstalado** | — |
| Uptime | 5 dias (sem reboot desde 16/07) | — |

768 dpi = 640 (pareado do 4K) + 20% ("Interface maior"). Ou seja: o aparelho
estava com o **modo TV 4K completo aplicado**, apesar de o registro dizer que
tudo fora revertido. Animações, zen_mode e demais settings estavam ok.

## Causa raiz (confirmada no código)

1. Em algum momento das alternâncias, o **`phoneRevert`** (retrato "vivo" do
   modo celular, capturado no `wakeOneImpl` a cada ida ao TV) foi gravado **já
   contaminado com valores de TV** — risco estrutural: só a ROTAÇÃO tinha
   proteção contra isso (exceções em `sleepOneImpl`/`wakeOneImpl`).
2. "Voltar ao celular" então **reescrevia os valores de TV** achando que era o
   estado do celular, e marcava as entradas como dormentes — a interface
   "não encaixava", mas o app considerava a volta um sucesso.
3. A **Reversão completa** descartava entradas dormentes **sem tocar no
   aparelho** (`revert:one`: "Já estava desfeito (modo celular)") — as
   entradas de resolução/dpi/fonte foram removidas do registro com o aparelho
   ainda em modo TV, **perdendo o estado original registrado**.

## Restauração manual (comandos executados, com reversão anotada)

Estado alvo = padrão de fábrica do display. Valores de TV anteriores (para
reverter a restauração, se preciso): override 3840x2160, densidade 768,
fonte 1.15.

```
wm size reset                     # tira o override 3840x2160
wm density reset                  # tira o override 768
settings put system font_scale 1.0        # era 1.15
wm fixed-to-user-rotation disabled        # já estava disabled; garantia
cmd package set-home-activity com.sec.android.app.launcher   # não havia padrão
input keyevent 3                  # traz o launcher para a tela
```

## Verificação (DEPOIS)

- `wm size` → só Physical 1080x2340 (sem override) ✔
- `wm density` → só Physical 480 (sem override) ✔
- `display_size_forced` / `display_density_forced` → vazios ✔
- `font_scale` → 1.0 ✔
- `cmd shortcut get-default-launcher` → One UI Home
  (`com.sec.android.app.launcher`) ✔ e em primeiro plano ✔
- Rotação mantida em accel 0 / rot 0 — igual ao original registrado. ✔

Nota de Android 16: `cmd package resolve-activity --brief -c
android.intent.category.HOME` responde "No activity found" mesmo com launcher
padrão definido — a leitura confiável é `cmd shortcut get-default-launcher`
(que já é o caminho primário do `getCurrentHome` no `adb.js`).

## Consequências no código (aplicadas hoje — ver `mudanças-21-07-2026.md`)

- **Reset de interface** (novo): devolve a interface de celular ao estado
  ORIGINAL da primeira configuração, mantendo apps e o perfil TV.
- **Fim do descarte cego de entradas dormentes** no `revert:one`: antes de
  esquecer, confere no aparelho se o estado original vale; se não, reverte de
  verdade.

## Pendências deste aparelho

- Entradas Max/Paramount+ no registro apontam apps que já não existem
  (reversão sempre falhará) — limpar quando houver limpeza de entradas órfãs.
- Perfil "s21fe celular" contém dpi de TV (320) — a usuária decide se apaga.
- Falta a usuária validar visualmente o aparelho e, depois, o fluxo novo de
  Reset de interface.
